- Команда: K14

- Версия: 1.0
- Дата: 22.11.2026

## Что является объектом

Один объект — один эпизод BabyAI PutNext. В форме видны анонимный ID эпизода, текст миссии из JSON и видео с действиями агента. Оценивайте действие агента и итоговое положение предметов по видео.

В миссии `put the red ball next to the blue box` предмет **A** — красный мяч, который нужно взять и перенести. Предмет **B** — синяя коробка, рядом с которой нужно положить мяч. Для человеческой оценки «рядом» означает клетку с общей стороной с клеткой B. Если клетки соприкасаются только углом, условие миссии не выполнено.

Цель аудита — проверить, насколько сигнал успеха BabyAI PutNext совпадает с человеческой оценкой выполнения миссии. Оценку по видео ставьте по правилам этой инструкции.

## Метки и правила

| `label` | Когда ставить |
| --- | --- |
| `1` | Агент взял предмет A и положил его на клетку с общей стороной с клеткой B. На последнем кадре оба предмета остаются в таком положении. По видео видна связная последовательность действий от выбора A до его размещения рядом с B. Обход, лишние повороты и повторные попытки допустимы. |
| `0` | По видео видно, что критерий для `1` не выполнен. Например, агент перенёс B к A, оставил A в руках, положил его по диагонали от B или рядом с другим предметом. Ставьте `0` также при стартовом соседстве без нового подходящего переноса A или при очевидно случайном достижении цели. |
| `Н/О` | Видео не открывается, отсутствует нужный фрагмент, предметы нельзя различить или миссия отсутствует. Укажите техническую причину в комментарии. |

При `0` выберите один код причины. При `1` или `Н/О` оставьте «нет кода».

| `reason` | Когда применять |
| --- | --- |
| `R1` | **Уже рядом на старте.** Клетки A и B изначально имеют общую сторону, и агент не выполнил нового подходящего переноса A. |
| `R2` | **Поменяны роли.** Агент перенёс B к A. В конце предметы рядом, но перемещён другой предмет. |
| `R3` | **Случайное достижение.** Правильное соседство возникло как очевидный побочный эффект беспорядочных перемещений или сбросов. |
| `R6` | **Прочее.** Например, A положен по диагонали от B, выбран другой предмет или эпизод завершился до выполнения задачи. Коротко опишите, что видно в записи. |

### Коды для анализа после разметки

Координатор сохраняет независимые оценки для расчёта согласия. Если оценки расходятся, итоговую метку фиксируют отдельно после разбора. Затем координатор сопоставляет итоговую метку с сигналом среды по ID эпизода. В форме для слепой разметки кнопок `R4` и `R5` нет, а коды анализа записываются отдельно от исходных кодов разметчика.

| Код | Когда применять |
| --- | --- |
| `R4` | **Ошибка выдачи награды.** Среда засчитала успех, и проверка лога подтвердила, что сигнал ошибочен по правилам самой среды. Для этого кода одного расхождения с человеческой оценкой недостаточно. |
| `R5` | **Пропуск успеха средой.** Итоговая человеческая оценка равна `1`, а среда успех не засчитала. Например, агент последовательно перенёс A на клетку с общей стороной с клеткой B, по итогам человеческой разметки получилась `1`, а у среды `success = false`. |

## Неоднозначные случаи

- Если подходят несколько кодов, проверьте их в порядке `R1` → `R2` → `R3` → `R6`. Если A и B были рядом с самого начала, но агент выполнил новый подходящий перенос A, оцените действия по общим правилам.
- Если правильная последовательность видна, но агент сделал много лишних шагов, применяйте обычный критерий `1`. Для `R3` нужны наблюдаемые признаки случайного размещения.
- Если запись целая и видно, что эпизод закончился до выполнения задания, ставьте `0` с `R6`. Если запись обрывается и итог неизвестен, ставьте `Н/О` с комментарием.
- Примеры. `1` без кода — «Агент взял красный мяч и положил его на клетку сразу слева от синей коробки». `0 / R2` — «Агент перенёс синюю коробку к красному мячу». `0 / R6` — «Мяч лежит по диагонали от коробки, клетки соприкасаются только углом». `Н/О` — «Запись обрывается до размещения мяча».
- Если правило допускает разные трактовки, запишите наблюдение в комментарии. Обсудите такой случай после сохранения независимых оценок.

## Для парных сравнений

`PAIRWISE_TASK = False`, `order = NA`. Каждый разметчик оценивает отдельный эпизод по миссии и видео. Назначенная пара означает двух участников, которые независимо размечают один эпизод. Обозначения A и B относятся к предметам в миссии.

## Ограничения

- До завершения независимой человеческой разметки не открывайте `scorer.jsonl`, исходные JSON с метаданными или ответы других участников. Используйте миссию, показанную в форме. Названия исходных файлов, тип политики, награда и сигнал успеха могут раскрывать ожидаемую оценку.
- Работайте с одной полной распакованной папкой эпизодов. Форма присваивает ID по позиции в списке файлов, отсортированном по имени. Если загрузить только файлы своей пары или изменить состав и порядок существующих файлов, ID могут сместиться.
- Колонка `file` в экспорте содержит исходные имена файлов. Выгрузку передавайте координатору, а статусы в общей таблице обновляйте без оценок и кодов причин.

## Как работать в форме и сдать результаты

1. Скачайте `annotate.html` и архив с эпизодами. Распакуйте архив, откройте HTML в браузере и нажмите **«Выбрать папку episodes/»**. Укажите папку с видео и одноимёнными JSON.
2. Откройте назначенный ID в левом списке, прочитайте миссию и посмотрите видео до конца. Выберите оценку и при необходимости заполните код и комментарий. Нажмите **«Сохранить и далее»**. Если следующий эпизод вам не назначен, выберите нужный ID в левом списке.
3. Нажмите **«Экспорт CSV»**. Браузер скачает файл с полями `id`, `file`, `label`, `reason`, `comment`, `timestamp`. Проверьте список ID перед передачей. Экспорт может включать ответы из предыдущих сессий в том же браузере.
4. Передайте координатору отдельный CSV со своим именем или псевдонимом. Сохраните исходный экспорт для сверки. После передачи отметьте **«CSV сдан»** в таблице прогресса. Для `Н/О` сохраните в форме технический комментарий и отметьте **«Тех. вопрос»** в таблице до устранения проблемы.
